# Test 16: aircraft (MSFS 2024, full SDK simulation-variable set)

Reviewed source: the MSFS 2024 SDK documentation — all **1,354 documented
simulation variables** extracted from the official SimVars index
(docs.flightsimulator.com; extracted index captured in the knowledge
base). The largest documented-format validation in the set.

## The STRUCT_* confirmations

MSFS itself groups variables into exactly the tuples OGSA-TS defines —
strongest structural confirmation of the schema to date:

| MSFS structure variable | OGSA-TS destination |
|---|---|
| `STRUCT_BODY_VELOCITY` + `STRUCT_BODY_ROTATION_VELOCITY` | `bodyDynamics` inputs |
| `STRUCT_WORLDVELOCITY` + `STRUCT_WORLD_ACCELERATION` | `kinematics` |
| `STRUCT_BODY_ROTATION_ACCELERATION` | angular α — the lever-arm correction term (§ reference points), natively |
| `STRUCT_LATLONALT` / `STRUCT_LATLONALTPBH` | geo channels + Euler → `orientation` |
| `STRUCT_SURFACE_RELATIVE_VELOCITY` | air-relative velocity → `air.*` channels |
| `STRUCT_EYEPOINT_DYNAMIC_ANGLE/OFFSET`, `EYEPOINT_POSITION` | `namedPoints` (`driverEye`) — the pilot eye point is a published SDK datum |
| `STRUCT_ENGINE_POSITION` | `namedPoints` per engine (mount positions) |
| `STRUCT_AMBIENT_WIND` | `wind.*` channels / `Environment` |

## Core mapping

| MSFS variable | OGSA-TS destination | Class |
|---|---|---|
| `PLANE_PITCH/BANK/HEADING_DEGREES_TRUE` | `orientation` (Euler→quat; true heading) | recipe |
| `PLANE_LATITUDE/LONGITUDE/ALTITUDE` | geo channels | convention |
| `PLANE_ALT_ABOVE_GROUND` / `…_MINUS_CG` | `env.heightFromGround` — **two published AGL variants differing only by CG reference**: MSFS ships both because consumers could not agree on the reference; OGSA-TS's `referencePoint` declares it instead | convention |
| `VELOCITY_WORLD_X/Y/Z` | `kinematics.velocity` | direct |
| `VELOCITY_BODY_X/Y/Z` | body velocity → world via orientation | recipe |
| `ACCELERATION_WORLD_X/Y/Z` | `kinematics.acceleration` | direct |
| `ACCELERATION_BODY_X/Y/Z` | `bodyDynamics.specificForce` via gravity conversion (coordinate accel → accelerometer: `f = a − g` in body frame) | recipe |
| `ROTATION_VELOCITY_BODY_X/Y/Z` | `bodyDynamics.angularVelocity` | direct |
| `ROTATION_ACCELERATION_BODY_X/Y/Z` | channels (`air.alphaX/Y/Z`) — α for consumer lever-arm corrections | convention |
| `AIRSPEED INDICATED/TRUE`, `AIRSPEED MACH`, `GROUND_VELOCITY`, `VERTICAL_SPEED` | `air.*` channels | annex family |
| `AILERON/ELEVATOR/RUDDER POSITION/DEFLECTION(_PCT)`, trims | `ctrl.*` (third game: ratification evidence with X-Plane + DCS) | annex family |
| `GEAR_*_STEER_ANGLE`, `CENTER WHEEL RPM`, `GEAR SKIDDING FACTOR` | wheel drive points: `WheelExtended.steerAngle`, `WheelState.rpm`, `slip` | direct |
| `ENG N1/N2 RPM`, `GENERAL ENG THROTTLE LEVER POSITION`, `ENG FUEL FLOW PPH`, ITT | `engine.*` channels / `JetState.throttle` | annex |
| `AMBIENT WIND VELOCITY/DIRECTION/X/Y/Z`, `AMBIENT TEMPERATURE/PRESSURE/DENSITY/PRECIP/VISIBILITY`, `AMBIENT IN CLOUD` | `Environment` (density/temp/pressure) + `wind.*`/`env.*` channels | direct/annex |
| `SIM ON GROUND`, `PLANE_IN_PARKING_STATE`, `PLANE_TOUCHDOWN_*` | boolean channels; touchdown set → `impact.*` event channels | custom |
| `PUSHBACK_*` (attached, angle, contact xyz) | ground-vehicle object or channels — pushback tug as secondary object | convention |

## Notes

- **CG-reference disambiguation is MSFS's problem too**: publishing
  `PLANE_ALT_ABOVE_GROUND` *and* `…_MINUS_CG` is the silent-contract cost
  (test 12) paid in API surface — OGSA-TS pays it once in `referencePoint`.
- Angular acceleration is natively published — consumers doing lever-arm
  corrections need not differentiate `angularVelocity`.
- Naming is inconsistent in the source itself (`VELOCITY_BODY_X` vs
  `ACCELERATION BODY X`); senders normalize into OGSA-TS ratified names.
- MSFS senders will typically emit `bodyDynamics` (body-native set is
  fullest) — seventh source offering both frames.

## Verdict

**Covers — no adoptions; multiple structural confirmations.** The largest
documented variable set in the validation suite lands cleanly: STRUCT_*
composites mirror OGSA-TS's own groupings, per-instance positions (eyepoint,
engines) feed `namedPoints`, and the CG-relative AGL pair vindicates the
reference-point design.

Validation set: **16 tests, 6 source classes, zero open gaps.**
